TECSPA E2EE STATUS — ENCRYPTED WEB VAULT INTEGRATION (IN PROGRESS)

Implemented in this source update:
- Web members, chat, journal, front-history, and poll reads/writes use the client-encrypted vault adapter.
- Legacy web APIs that accepted or returned plaintext private content now fail closed with HTTP 410.
- Web imports write supported member/front-history/journal records through client-side encryption rather than legacy plaintext importer endpoints.
- Server-side vault stores encrypted payload envelopes only.

THIS IS NOT YET A COMPLETE E2EE RELEASE.
- Desktop SQLite still stores plaintext at rest; no SQLCipher integration or encrypted local-store migration has been completed.
- Sharing controls remain, but shared content endpoints are disabled until recipient key wrapping and encrypted shared-record delivery are implemented.
- Member avatar/banner object-storage migration and full encrypted media UX require follow-up; do not upload private media through legacy APIs.
- Existing plaintext database rows and media are not automatically migrated or erased. Existing plaintext data may already have been exposed to the server.
- Recovery-key flow, cross-device key recovery, hostile-server/client-code delivery threat, and independent security review are not complete.
- Type-check/build and end-to-end security tests must pass before calling this production-ready.

Never claim complete zero-knowledge security until every item above is implemented, migrated, and independently reviewed.
